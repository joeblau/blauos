# Editor layer: vim

This layer builds the pinned Vim release tarball (`vim-9.2.1175` in
`sources.lock.json` archives) for the independent ARM64 Darwin runtime. It
installs `/usr/bin/vim`. The build does not copy macOS executables or runtime
libraries; the executable links only the independently built
`/usr/lib/libSystem.B.dylib`.

The independent runtime provides libSystem only: no curses, termcap, terminfo,
iconv, X11, or gettext. Vim's autoconf configure cannot be used for this
profile because it probes and links host libraries and runs test binaries
against the host runtime. Instead the layer compiles upstream's own
`src/Makefile` object list (`OBJ_COMMON` + `OBJ_MAIN`, with the feature
variables empty) directly, with reviewed tracked replacements for the
generated headers:

- `config.h` replaces the autoconf `auto/config.h`. It selects the tiny
  feature set (`FEAT_TINY`), declares exactly the SDK headers and libSystem
  entry points the independent runtime provides, and enables `HAVE_TGETENT`
  backed by Vim's own `src/termlib.c`. Terminal capabilities come from Vim's
  builtin termcap entries (`ansi`, `vt320`, `vt52`, `xterm`, `dumb`), which
  cover a serial console.
- `osdef.h` replaces the `osdef.sh` output. With the SDK headers above, the
  only missing declarations are the termcap entry points that termlib.c
  defines.
- `termlib-tputs.patch` aligns the termlib `tputs()` output-callback type
  with the `int (*)(int)` form `term.c` uses on Unix (`TPUTSFUNCAST`), which
  modern clang otherwise rejects as an incompatible function pointer.

`auto/pathdef.c` is generated by the builder with the real compile and link
flags recorded in it and fixed `blauos-builder`/`blauos-build-host` identity
strings, keeping rebuilds comparable.

Build with a fresh output directory:

```sh
python3 scripts/blauos.py fetch-archives vim-9.2.1175
python3 scripts/vm/build_vim_commands.py \
  --archive .blauos/inputs/vim-9.2.1175.tar.gz \
  --runtime-root .blauos/build/runtime/root \
  --output .blauos/build/commands/vim-run-1
```

The builder verifies the archive SHA-256 against the lock before and after
compilation, refuses existing outputs, and emits an additive `root/`,
`provenance.json`, `commands.json`, `build.log`, and
`third-party-notices.txt` with the Vim license text. Compilation records
`guest_execution_verified: false`; actual guest behavior is verified
separately by `vm/commands/smoke.sh` (`vim --version` and `vim -es` ex-script
checks, which work over a plain serial line) through an authenticated,
unprivileged SSH session. Full-screen editing requires the interactive serial
console with `TERM` matching a builtin entry and is exercised manually.

The Vim license (charityware) applies; see `runtime/doc/uganda.txt` in the
pinned archive and the collected third-party notices.
